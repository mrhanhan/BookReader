# 私人书房（暂定名 BookrReader）设计文档

日期：2026-10-18
状态：待确认
定位：一个跑在自己服务器上、供 10-30 人小圈子自用的私人电子书阅读与图书管理产品。

---

## 1. 背景与意图

现有工具（以 NeatReader 为代表）有两个无法忍受的问题：

1. **PDF 被当成图片显示**：字体不能选、文字不能复制、布局不能调，阅读体验与电子书相差很远。
2. **个性化能力薄弱**：笔记散落、看不到阅读坚持、没有 AI 辅助。

本项目要做的是一个"私人书房"：书是自己的、数据是自己的、阅读是连续的。用户在手机 App、电脑客户端、网页三端使用同一个账号，打开任何一本书都能接着上次的位置读，笔记与书签始终都在；选中的段落可以就地让 AI 解释；所有划线批注汇入统一的笔记库；阅读的坚持被如实记录。

### 1.1 已确认决策

- 界面气质：纸墨书房（暖白纸色、衬线标题、克制留白）。
- 图书模式：圈子共享书架；进度、笔记、书签、AI 线程按用户独立。
- 三端含义：网页、Windows 桌面、Android 移动；第一版不做 iOS。
- 坚持天数口径：单日有效阅读 ≥10 分钟。
- 离线范围：自动缓存最近 5 本，可手动下载任意书。
- 本地预处理工具：第一版仅产品负责人自用，CLI 形态。
- 实时同步：SSE 推送，在线设备 5 秒内生效。
- 备份去向：产品负责人的本地高性能电脑（需常开或定时唤醒）。

## 2. 用户与规模

- 使用规模：10-30 人，邀请制注册，不对外开放注册，不商业化。
- 角色：管理员（首个账号，管理成员、邀请码、配额、备份状态）与成员。
- 图书模式：**圈子共享书架**——所有成员共用一批图书与共享分类；阅读进度、笔记、书签、AI 线程按用户各自独立、互不可见。
- 数据主权：所有电子书原文件、笔记、进度保存在用户自己的云服务器上；第三方 AI 只接收被提问的片段与必要上下文。

## 3. 目标 / 非目标 / 反目标

### 目标
- 支持 PDF、EPUB；MOBI/AZW3 导入时转换为 EPUB。
- 圈子共享书架：成员上传的书对所有人可见；删除由上传者或管理员执行。
- PDF 提供两种阅读模式：**原版模式**（可选中、复制、划线、裁边、适应宽度、夜间反色）与**重排模式**（字体、字号、行距、页边距、背景可调）。
- 扫描版 PDF 可经本地预处理工具生成文字层与重排版本。
- 三端（网页、Windows 桌面、Android 移动）共用同一套阅读内核与业务逻辑。
- 云端同步进度、笔记、书签、分类；离线可读可记，联网自动合并。
- 统一笔记库：跨书检索、按书/标签/时间筛选、跳回原文、导出 Markdown。
- AI 伴读：解释选中段落（带上下文）、总结本页/本章、追问、分析笔记。
- 阅读统计与"坚持天数"：单日有效阅读 ≥10 分钟计为有效。
- 自带部署与备份方案，跑在 4 核 8G / 100G 的自有云服务器上。

### 非目标（第一版不做）
- 微信小程序（接口预留，界面后续另写）。
- iOS 客户端（第一版移动端只交付 Android）。
- 导入外部平台的历史笔记。
- 商业化、订阅计费、公开注册、社交/书评社区。
- 移动端原生重写阅读器（先用 Capacitor 壳，性能不足再下沉）。
- 服务端 GPU / 在线 OCR（预处理在用户本地高性能电脑上完成）。

### 反目标（即使功能齐全也算失败）
- 丢数据：笔记或进度因同步冲突、误删、服务器故障而丢失。
- PDF 仍然"像一张图"：无法选中文字、无法复制。
- 同步需要手动点击，或换设备后找不到位置。
- AI 脱离原文胡答，或把整本书无提示地发给第三方。
- 界面堆满功能，破坏阅读的安静感。

## 4. 核心场景

1. **通勤读**：手机打开昨夜未读完的书，直接落到上次位置；选中一段划线并写一句批注；地铁断网也能继续。
2. **书桌读**：电脑客户端打开同一本书，进度与刚写的批注已同步；切换到重排模式，调大字号、换暖色背景。
3. **快速查阅**：网页端搜索笔记库里的关键词，找到三个月前的一条批注，点击跳回原书位置。
4. **读不懂**：选中一段晦涩文字，点"解释"，AI 结合本页上下文给出通俗解释，可继续追问。
5. **扫描书入库**：产品负责人在本地 5080 电脑上用预处理工具把扫描 PDF 转成带文字层/可重排的版本，检查后连同原书一起上传到共享书架。
6. **回望**：统计页看到连续坚持天数、本周阅读时长、读完的书；AI 分析某本书的笔记主题。

## 5. 功能规格

### 5.1 账号与圈子
- 邀请码注册：管理员生成一次性邀请码，可设置有效期。
- 登录：用户名 + 密码；密码 Argon2id 哈希；Access Token（15 分钟）+ Refresh Token（30 天，可撤销）。
- 设备管理：查看已登录设备，可远程注销。
- 成员管理（管理员）：禁用账号、重置密码、设置存储配额。
- 存储采用共享池 + 每成员上传配额；管理员可调。
- 共享书架权限：成员可上传与阅读；成员只能删除自己上传的书；管理员可删除任意书。

### 5.2 书架与图书导入
- 支持格式：PDF、EPUB；MOBI/AZW3 在服务端用 Calibre 转换为 EPUB 后入库（原始文件保留）。
- 导入路径：Web 上传（分片/断点续传）、桌面端本地文件直接读取后上传、移动端文件选择器。
- 自动提取元数据与封面；允许手动编辑书名、作者、简介、封面。
- 分类与标签：多对多；支持自定义分类、颜色、排序；支持全文搜索书名/作者。
- 书架视图：封面网格 / 列表；排序（最近阅读、导入时间、书名）；筛选（分类、格式、未读/在读/读完）。
- 图书状态：未读、在读、读完；显示进度百分比。
- 删除：软删除进回收站，30 天后清理；删除需二次确认。
- 存储用量：展示共享池已用/总量、本成员上传用量、单本大小；超过 90% 提示。
- 共享规则：所有人可见可读；分类与标签为书架级共享，成员可创建，管理员可整理；删除权限见 5.1。

### 5.3 阅读器
统一阅读内核（`packages/reader-core`），对上层暴露 `ReaderEngine` 接口。

**PDF 原版模式**
- pdf.js 渲染 canvas + 文字层；文字层支持选中、复制。
- 划线：按文字偏移或规范化矩形存储，颜色可选。
- 版面：适应宽度、实际大小、缩放、单页/双页/连续滚动。
- 裁边（自动检测白边 + 手动微调）、夜间反色、亮度调节。
- 页码跳转、目录（有书签则用，否则按页）。

**PDF 重排模式**
- 读取预处理工具产出的重排包（结构化块 + 原文映射）。
- 可调：字体族（默认衬线宋体类）、字号、行距、页边距、背景主题（纸白/米黄/护眼绿/深色）。
- 图片、表格、公式以块级元素保留；解析失败的块回退为原页截图。
- 与原版模式一键切换；位置双向映射（精确映射来自预处理包，缺失时按页码近似）。

**EPUB 模式**
- epub.js 渲染，流式重排；字体、字号、行距、主题可调。
- 目录、进度、双栏（大屏）、翻页/滚动切换。

**通用**
- 记录位置使用的定位器（locator）而非页码：EPUB 用 CFI；PDF 原版用页码 + 页内归一化矩形 + 页内文字偏移；重排用源页码 + 字符区间 + 块 ID。
- 阅读中工具栏最小化，点击/快捷键唤出。
- 快捷键（桌面）：翻页、目录、笔记、AI、全屏、夜间模式。
- 自动保存进度（节流，最多每 5 秒一次本地写入，30 秒或离开时同步）。

### 5.4 笔记与书签
- 划线（高亮）与批注（划线 + 文字）两种；颜色 5 种。
- 笔记与书签按用户隔离：共享书架上的书，其他成员看不到你的划线与批注。
- 标签：自由标签，可多选；标签用于笔记库筛选。
- 书签：轻量位置标记，可加备注。
- 笔记库：全局视图，支持全文检索（含划线原文与批注文字）、按书/标签/时间筛选、按书分组。
- 跳转：点击任意笔记回到原书位置并高亮。
- 编辑与删除：笔记可编辑文字、改颜色/标签；删除进回收站（30 天）。
- 导出：单本或筛选结果导出 Markdown（含书名、位置、划线原文、批注、时间）。
- 冲突策略：同一条批注在两台设备同时编辑文字时，保留较新版本并把旧版本存入历史，不静默丢失。

### 5.5 AI 伴读
- 入口：选中文字后的悬浮菜单（解释 / 总结本页 / 提问）；侧栏 AI 面板。
- 能力：
  1. **解释段落**：结合所选文字 + 当前页/当前章上下文，用通俗语言解释。
  2. **总结**：总结当前页、当前章。
  3. **追问**：多轮对话，保留线程。
  4. **笔记分析**：对一本书或一批笔记做主题归纳、观点梳理、待办提取。
- 上下文组装：选中文本 + 当前页文本（或本章截断至 token 预算）+ 书名/作者；默认预算 8k tokens。
- 模型：服务端 AI 网关，OpenAI 兼容协议；默认 DeepSeek（解释与总结用 deepseek-chat，笔记分析用 deepseek-reasoner），可配置切换。
- 流式输出（SSE）；首字延迟目标 ≤3 秒。
- 线程按书保存，可回看、删除。
- 配额：每用户每日/每月 token 上限，管理员可调；超限提示。
- 隐私：仅发送必要片段；设置页说明数据流向；提供"禁用 AI"开关。
- 失败处理：超时/额度用尽/网络错误给出明确提示，不丢用户已输入的问题。

### 5.6 阅读统计与坚持天数
- 计时口径：阅读器可见且处于前台时累计；无操作超过 2 分钟暂停计时；每 30 秒打点一次。
- 有效阅读：当天累计有效阅读 ≥10 分钟，该天计为"有效阅读日"。
- 坚持天数：截至今天（若今天尚未达标，则截至昨天）连续的有效阅读日数。
- 时区：按用户设置的时区计算（默认 Asia/Shanghai），跨时区旅行不重复/不丢失。
- 统计页：连续天数、累计有效天数、本周/本月阅读时长、每日时长柱状图、读完的书数量、最常读的书。
- 数据来源：reading_sessions 聚合为 daily_stats；统计只读，不得影响阅读性能。

### 5.7 同步
- 本地优先：所有写操作先落本地数据库并标记待同步，界面立即生效。
- 需要同步的实体：图书元数据、分类、进度、划线/批注、书签、AI 线程/消息、阅读会话、设置。
- 服务端为每个用户维护单调递增的变更日志（sync_changes）；客户端凭游标增量拉取。
- 推送幂等：以客户端生成的 UUIDv7 为主键；重复推送不产生重复数据。
- 冲突：标量字段（进度、元数据）按"客户端更新时间 + 服务端接收顺序"决定；集合类（笔记）逐条合并；文字编辑冲突保留新旧两版。
- 删除：留墓碑（deleted_at），保证删除能传播；墓碑 90 天后清理。
- 设备时钟偏移：服务端拒绝超前 5 分钟以上的客户端时间，以服务端接收时间兜底。
- 触发：应用启动、回到前台、网络恢复、写操作后 2 秒（防抖）、每 60 秒心跳。
- 实时推送：服务端通过 SSE 向在线设备推送变更；同一用户的其他设备在 5 秒内收到并应用；断线自动重连并以游标补齐。
- 状态可见：同步中/已同步/离线待同步/冲突已解决。

### 5.8 管理后台
- 成员列表与配额、邀请码管理。
- 存储总览：总容量、已用、各成员占用、单书大小 Top 榜。
- 备份状态：最近成功时间、失败告警。
- 系统设置：AI 模型与 Key、每用户 AI 配额、注册开关、时区默认值。
- 审计日志：登录、删除图书、管理员操作。

### 5.9 离线策略
- 自动缓存最近阅读的 5 本书；用户可手动"下载到本机"任意图书，手动下载不参与 LRU 淘汰。
- 缓存内容：原书文件、重排包、文字层；封面按需缓存。
- 淘汰：只淘汰未固定的离线书，按最近阅读时间 LRU；正在读的书与手动固定的书不淘汰。
- 笔记、书签、进度永远写入本地库（IndexedDB / 原生 SQLite），不参与任何缓存淘汰；未同步数据不会因清理离线书而丢失。
- 离线期间可读、可划线、可批注、可写书签；AI 不可用并给出明确提示。
- 存储位置：Web 使用 OPFS 存大文件；Android 使用应用私有目录；桌面使用应用数据目录。
- 显示离线缓存占用，支持一键清理未固定的缓存。

## 6. 技术架构

### 6.1 仓库结构（pnpm + Turborepo）
```
apps/
  web/          React + Vite + TypeScript（主界面，也是三端的共同前端）
  desktop/      Tauri 2 壳（加载 web 构建产物 + 原生文件访问）
  mobile/       Capacitor 7 壳（Android，加载同一 web 构建）
  server/       Fastify + TypeScript（API、同步、AI 网关、文件服务）
packages/
  reader-core/  阅读内核（pdf.js / epub.js 封装，框架无关）
  ui/           设计系统与组件（纸墨书房主题）
  shared/       类型、校验（zod）、定位器与同步协议
tools/
  pdf-preprocess/  本地预处理工具（Python，独立环境，非服务端部署）
```

### 6.2 前端
- React 19 + Vite + TypeScript；Tailwind CSS；Zustand（阅读态）+ TanStack Query（服务端数据）；React Router。
- 本地数据库：Web 用 Dexie（IndexedDB）；桌面/移动 WebView 同一套；大文件缓存走文件系统/原生存储。
- 设计系统：纸墨书房——暖白纸色、衬线标题、克制留白；阅读页与控制栏分离，控制栏按需浮现。
- PWA：可安装、离线打开最近读过的书。

### 6.3 阅读内核
- PDF：pdf.js（文字层、选择、渲染）。
- EPUB：epub.js。
- 统一 ReaderEngine 接口：open / render / getLocator / goTo / selection / highlight / theme / destroy。
- 定位器与原文映射是内核的核心抽象，三端共用。

### 6.4 服务端
- 运行时：Node.js 22 + Fastify + TypeScript。
- 数据库：PostgreSQL 16 + Drizzle ORM。
- 对象存储：MinIO（S3 协议），使用预签名 URL 直传/直取，服务端不经手大文件流量。
- 认证：Argon2id + JWT（access/refresh）。
- AI 网关：OpenAI 兼容客户端；Key 用 AES-GCM 加密存库；SSE 流式转发；提示词模板版本化。
- 实时通道：SSE（Server-Sent Events）按用户推送同步变更，支持断线重连与游标补齐。
- 背景任务：缩略图/封面生成、MOBI/AZW3 转换（调用 Calibre CLI）、统计聚合、备份触发。
- 日志：pino 结构化日志；禁止记录书籍正文与用户笔记内容。

### 6.5 桌面端与移动端
- Tauri 2：Windows 优先，macOS 可选；原生文件选择与本地缓存目录；自动更新可选。
- Capacitor 7：仅 Android（APK 侧载分发）；原生文件选择、安全存储、应用生命周期触发同步。第一版不做 iOS 客户端。

## 7. 数据模型（核心表）

- `libraries`：id, name, created_at（第一版单库，为将来多库预留）
- `users`：id, username, password_hash, display_name, role, upload_quota_bytes, timezone, ai_enabled, created_at
- `invites`：code, created_by, expires_at, used_by, used_at
- `devices`：id, user_id, name, platform, last_seen_at, refresh_token_hash
- `books`：id, library_id, uploaded_by, title, author, description, format, original_filename, original_size, sha256, file_key, cover_key, text_layer_key, reflow_key, status, deleted_at, created_at, updated_at
- `categories`：id, library_id, name, color, sort_order
- `book_categories`：book_id, category_id
- `reading_progress`：user_id, book_id, locator(jsonb), percent, updated_at, device_id
- `annotations`：id, user_id, book_id, type(highlight|note), color, locator(jsonb), selected_text, note_text, tags(text[]), revision, deleted_at, created_at, updated_at
- `annotation_history`：id, annotation_id, note_text, edited_at, device_id
- `bookmarks`：id, user_id, book_id, locator(jsonb), label, deleted_at, created_at
- `reading_sessions`：id, user_id, book_id, device_id, started_at, ended_at, active_seconds, pages_read
- `daily_stats`：user_id, local_date, active_seconds, qualified(bool)
- `ai_threads`：id, user_id, book_id, title, anchor_locator(jsonb), created_at
- `ai_messages`：id, thread_id, role, content, model, token_usage, created_at
- `sync_changes`：revision(bigserial), user_id, entity_type, entity_id, op, payload(jsonb), created_at
- `audit_logs`：id, user_id, action, target, metadata(jsonb), created_at

### 定位器（locator）约定
```json
// EPUB
{ "kind": "epub", "cfi": "epubcfi(...)", "href": "chapter3.xhtml", "percent": 0.62 }
// PDF 原版
{ "kind": "pdf", "page": 128, "rect": {"x":0.12,"y":0.31,"w":0.7,"h":0.02}, "charOffset": 340, "percent": 0.62 }
// 重排
{ "kind": "reflow", "sourcePage": 128, "blockId": "b_142", "charRange": [12, 88], "percent": 0.62 }
```
重排包中每个块携带 sourcePage 与源文字区间，用于双向映射；无映射时按 sourcePage 近似。

## 8. 关键技术决策与取舍

| 决策 | 选择 | 理由 | 代价 |
|---|---|---|---|
| 跨端方案 | Web 内核 + Tauri/Capacitor 壳 | 阅读交互三端一致，一套代码 | 移动端大 PDF 性能需原生兜底 |
| PDF 渲染 | pdf.js | 成熟、可提取文字层、支持选择 | 重排需另做预处理 |
| 重排位置 | 本地预处理工具产出重排包 | 不占服务器算力，可利用 5080 | 用户多一步预处理 |
| 扫描件 OCR | 不放进应用，本地工具完成 | 服务端仅 4C8G 无 GPU | 入库前需人工检查 |
| 同步 | 本地优先 + 变更日志 + 游标拉取 | 离线可用、增量传输 | 冲突合并逻辑复杂 |
| 存储 | MinIO + 预签名 URL | 服务端不中转大文件 | 需维护对象存储 |
| AI | 服务端网关 + OpenAI 兼容 | 可换模型、Key 不落客户端 | 需管理配额与隐私 |
| 小程序 | 第一版不做 | 工期与渲染能力限制 | 后续需另写界面 |

## 9. 本地预处理工具（tools/pdf-preprocess）

- 运行环境：用户本地高性能电脑（Windows + NVIDIA 5080），Python，独立环境；不部署到服务器。
- 输入：PDF 文件（文字版或扫描版）。
- 处理流程：
  1. 判断是否含可用文字层。
  2. 文字版：PyMuPDF 抽取文字与坐标；版面分析（Docling 或 MinerU）识别标题、段落、图片、表格、公式、页眉页脚。
  3. 扫描版：GPU OCR（PaddleOCR / MinerU），保留版面结构。
  4. 可选：调用 DeepSeek 对 OCR 结果做纠错与断行合并（需用户确认联网与费用）。
  5. 产出：`*.bookr.json` 重排包（块结构 + 源页映射 + 元数据）+ 可选带文字层的 PDF。
- 输出要求：schema 版本化；失败块标注并以原页截图回退；生成质量报告（页数、识别置信度、回退页列表）。
- 使用方式：CLI 优先（可批量），后续可加简单桌面界面。
- 校验：上传重排包时服务端校验 schema 版本与书籍 sha256 匹配。

## 10. 阶段划分（三端并行）

每个阶段结束都应是可真实使用的增量；阅读内核与业务逻辑共享，三端壳从阶段 2 起同步接入。

- **P0 基础设施**：monorepo、CI、Docker Compose（Postgres/MinIO/Server/Caddy）、账号与邀请码、设计系统骨架。
- **P1 书架与导入**：上传（直传 MinIO）、元数据/封面、分类标签、书架界面、MOBI/AZW3 转换、配额与回收站。
- **P2 阅读内核 v1**：EPUB + PDF 原版模式；选中/复制/划线/批注/书签；纸墨书房阅读主题；进度本地保存；Tauri 桌面壳与 Android Capacitor 壳接入。
- **P3 预处理与重排**：本地工具、重排包上传、重排模式、双模式位置映射、字体/主题设置。
- **P4 同步**：变更日志、SSE 实时推送、离线队列、冲突合并、离线缓存管理（最近 5 本 + 手动固定）、三端联调、设备管理。
- **P5 AI 伴读**：网关、解释/总结/追问、上下文组装、流式输出、配额。
- **P6 笔记库与 AI 分析**：全局笔记视图、检索筛选、跳转、导出、笔记分析。
- **P7 统计与坚持**：计时、会话聚合、有效阅读日、统计页与图表。
- **P8 管理与交付**：管理后台、备份与恢复演练、监控告警、PWA/安装包、验收测试。

## 11. 部署与运维

- 服务器：4 核 8G / 100G，自有云服务器。
- 部署形态：Docker Compose 单机；Caddy 负责 HTTPS 与静态站点；域名与证书由用户提供。
- 存储规划：100G 中预留数据库与备份空间；客户端显示用量；接近阈值告警。
- 备份：
  - PostgreSQL：每日 pg_dump，保留 30 天，并随对象存储备份一并复制到本地备份机。
  - MinIO 与 pg_dump：每日用 restic 增量备份到产品负责人的本地高性能电脑（需常开或定时唤醒），保留 30 天；由备份机主动拉取，服务器无需访问家庭网络。
  - 备份失败，或本地备份机连续 24 小时未上报，触发告警。
  - 每季度做一次恢复演练并记录。
- 监控：健康检查、磁盘使用率、备份失败告警（邮件或 Webhook）。
- 升级：镜像版本化，迁移脚本随发布执行；升级前自动备份。

## 12. 安全与隐私

- 邀请制；密码 Argon2id；刷新令牌可撤销；登录失败限流。
- 所有数据按 user_id 隔离；对象存储使用短时效预签名 URL。
- AI Key 服务端加密存储，永不下发客户端；日志不记录书籍正文与笔记。
- AI 请求仅发送选中片段与必要上下文；设置页明确说明；可全局关闭。
- 管理后台操作写审计日志。
- 上传文件类型与大小校验；解析库在隔离进程中运行。

## 13. 验收标准

1. 上传 300 页文字版 PDF，10 秒内可打开；原版模式可选中、复制、划线、加批注。
2. 预处理后的书可切换重排模式，字体/字号/行距/主题可调；切回原版位置不丢失（误差 ≤1 页）。
3. 同一账号三端：手机划线后，电脑 5 秒内出现；断网记录笔记，联网后自动合并，无丢失。
4. 选中段落请求解释，首字 ≤3 秒返回，解释内容引用了本页上下文。
5. 单日有效阅读 ≥10 分钟计入当天；连续天数在跨天、跨时区场景下正确。
6. 笔记库可全文搜索，能按书/标签筛选、跳回原文、导出 Markdown。
7. 扫描版 PDF 经预处理后可选中文字并划线。
8. 模拟数据库损坏，可从备份恢复到最近一次成功备份，笔记与进度完整。
9. 网页、Windows 桌面、Android 三端界面均符合"纸墨书房"设计语言，阅读页无多余干扰。
10. 成员 A 上传的书，成员 B 登录后可见并可阅读；B 的笔记与进度对 A 不可见；B 不能删除 A 上传的书。
11. 断网时最近 5 本可打开阅读与记笔记；清理离线缓存不影响未同步的笔记。
